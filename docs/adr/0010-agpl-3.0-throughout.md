# AGPL-3.0 for the entire repository

Everything — extension, pipeline, Workers, artifacts tooling — is AGPL-3.0.

## Why

The asset worth protecting is the **Discussion Index pipeline**: the crawled, canonicalized, deduplicated record of what the internet has discussed. The extension is replicable by anyone with time; the index is not. AGPL's network clause means anyone running a hosted fork must publish their changes, so the project cannot be taken closed-source and used to out-compete itself. This is compatible with the no-lock-in promise in [ADR 0002](./0002-stack-effect-v4-alchemy-wxt-cloudflare.md): anyone may still deploy the whole stack to their own Cloudflare account and point their install at it — they simply cannot do so privately.

## Considered Options

- **Apache-2.0 client / AGPL-3.0 backend** — the common split, keeping the extension maximally reusable and its patent grant intact for store distribution, while protecting the pipeline. Rejected in favour of one unambiguous license across the repo.
- **MIT/Apache throughout** — maximum adoption and contribution; rejected because it permits a closed fork of the pipeline.

## Consequences

- Some organisations ban AGPL outright. This will cost contributors, and it forecloses anyone embedding the client in a proprietary product. That is an accepted trade.
- Apache-2.0's explicit patent grant is not present. For an extension distributed through app stores this is a real, if small, difference in exposure.
- Store distribution itself is unaffected — AGPL binaries ship to the Chrome Web Store and App Store without issue, provided the corresponding source is available, which it is.
